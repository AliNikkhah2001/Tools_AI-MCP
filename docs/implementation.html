Implementation Guide

Step-by-step guide to building your own LLM-controlled multi-agent coding pipeline with OpenCode.

1 Foundation: Agent Configuration

Start by defining your specialized agents in .opencode/agents/. Each agent should have a clear role and capabilities.

// .opencode/agents/orchestrator.md
---
name: orchestrator
model: anthropic/claude-sonnet-4-20250514
temperature: 0.3
tools:
  - Bash
  - Read
  - Grep
  - Glob
  - Task
---

You are the master orchestrator. Your job is to:
1. Analyze incoming tasks
2. Break them into subtasks
3. Route subtasks to appropriate specialist agents
4. Monitor progress and handle failures
5. Aggregate results

When delegating, use the Task tool with appropriate subagent_type.
// .opencode/agents/coder.md
---
name: backend-coder
model: anthropic/claude-sonnet-4-20250514
temperature: 0.2
tools:
  - Bash
  - Read
  - Write
  - Edit
  - Glob
  - Grep
---

You are a backend coding specialist. Your expertise includes:
- API development (REST, GraphQL)
- Database design and queries
- Server-side logic
- Authentication and security

Write clean, tested, production-ready code.
Tip: Start with 3-4 agents (orchestrator, coder, reviewer, tester) and expand as needed.

2 Permission Auto-Accept Configuration

Configure OpenCode to automatically accept permissions for low-risk operations while requiring confirmation for dangerous ones.

// opencode.json - Permission configuration
{
    "permissions": {
        "auto_accept": {
            "read": ["*"],
            "write": ["*.md", "*.txt", "*.json"],
            "bash": {
                "allowed": [
                    "npm test",
                    "npm run lint",
                    "git status",
                    "git diff",
                    "ls",
                    "cat",
                    "head",
                    "tail"
                ],
                "requires_confirmation": [
                    "rm -rf",
                    "git push",
                    "npm publish",
                    "docker",
                    "sudo"
                ]
            }
        }
    }
}
Warning: Always require confirmation for destructive operations (rm, git push --force, database migrations).

3 Custom Commands for Orchestration

Create custom commands that enable the orchestrator to manage the pipeline.

// .opencode/commands/orchestrate.md
---
description: Orchestrate a complex task across multiple agents
allowed-tools: Task, Bash, Read, Grep, Glob
---

Break down the task: $ARGUMENTS

1. Analyze the requirements
2. Create a task breakdown
3. Delegate to appropriate agents:
   - Use Task with subagent_type "backend" for server-side work
   - Use Task with subagent_type "frontend" for UI work
   - Use Task with subagent_type "test" for testing
4. Monitor progress
5. Report results
// .opencode/commands/review.md
---
description: Review code changes with quality checks
allowed-tools: Read, Grep, Bash
---

Review the recent changes:

1. Check code quality
2. Run tests: npm test
3. Run linter: npm run lint
4. Check for security issues
5. Provide summary with issues found

Implement a monitoring dashboard to track agent activity and progress.

// .opencode/commands/dashboard.md
---
description: Show current pipeline status
allowed-tools: Bash, Read, Grep
---

Display the current pipeline status:

1. Check running agents: ps aux | grep opencode
2. Read recent logs: tail -100 .opencode/logs/*.log
3. Show task queue status
4. Display metrics:
   - Tasks completed today
   - Success rate
   - Average completion time

For a web-based dashboard, consider:

  • MLflow: Experiment tracking and monitoring

5 Continuous Operation Loop

Implement the never-stopping loop that keeps the pipeline running.

// .opencode/commands/continuous.md
---
description: Start continuous operation mode
allowed-tools: Task, Bash, Read, Write, Edit
---

Start continuous operation:

1. Initialize task queue
2. Loop:
   a. Check for pending tasks
   b. If tasks available:
      - Pick highest priority task
      - Delegate to appropriate agent
      - Wait for completion
      - Log results
      - Update dashboard
   c. If no tasks:
      - Check for new user input
      - Run maintenance tasks
      - Optimize agent prompts (self-improvement)
   d. Sleep briefly
   e. Repeat
Key Insight: The loop should include a self-improvement step where the system analyzes its own performance and adjusts.

6 Self-Improvement Integration (SICA)

Implement the self-improvement loop based on the SICA paper.

// .opencode/commands/self-improve.md
---
description: Analyze and improve agent performance
allowed-tools: Read, Write, Edit, Bash
---

Analyze recent performance and improve:

1. Collect metrics from last N tasks
2. Identify patterns:
   - Which tasks succeeded/failed
   - Common error types
   - Time per task type
3. Generate improvement suggestions:
   - Prompt modifications
   - Tool configuration changes
   - Workflow optimizations
4. Apply improvements to agent configs
5. Test improvements on sample tasks
6. Log improvement results

This implements the core idea from SICA: the agent edits itself based on experience.

7 Experience Replay (CER)

Implement contextual experience replay for learning from past tasks.

// .opencode/skills/experience-replay/
// skill.md
---
name: experience-replay
description: Learn from past task experiences
tools: Read, Write, Grep
---

Store and retrieve task experiences:

## Store Experience
After completing a task, store:
- Task type and description
- Approach used
- Success/failure
- Metrics (time, quality, issues)
- Lessons learned

## Retrieve Experience
When facing a new task:
1. Search for similar past tasks
2. Review approaches that worked
3. Avoid approaches that failed
4. Apply relevant lessons
// .opencode/skills/experience-replay/scripts/store.sh
#!/bin/bash
# Store task experience
TASK_TYPE=$1
OUTCOME=$2
METRICS=$3
LESSONS=$4

echo "{
    \"timestamp\": \"$(date -Iseconds)\",
    \"task_type\": \"$TASK_TYPE\",
    \"outcome\": \"$OUTCOME\",
    \"metrics\": $METRICS,
    \"lessons\": $LESSONS
}" >> .opencode/experiences.jsonl

8 Rules for Safety and Quality

Establish rules that ensure safe and high-quality operation.

// .opencode/rules/safety.md
---
globs: ["**/*"]
alwaysApply: true
---

## Safety Rules

1. **Never commit secrets**: Check for API keys, passwords, tokens
2. **Validate inputs**: Sanitize all user inputs
3. **Error handling**: Always handle errors gracefully
4. **Logging**: Log all significant actions
5. **Rollback**: Always have a rollback plan

## Quality Rules

1. **Test coverage**: Minimum 80% for new code
2. **Code review**: All changes must be reviewed
3. **Documentation**: Public APIs must be documented
4. **Performance**: No regressions in benchmarks
