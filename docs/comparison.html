Key Differences

SICA vs Self-Harness

  • SICA: Agent modifies its own prompts and tools
  • Self-Harness: The entire control infrastructure (harness) is optimized
  • Key difference: Self-Harness operates at a higher abstraction level — it improves the system that controls the agent, not just the agent itself

AlphaEvolve vs Traditional Approaches

  • AlphaEvolve: Uses evolutionary algorithms with LLMs as mutation operators
  • Traditional: Uses LLMs for direct code generation
  • Key difference: AlphaEvolve maintains a population of solutions and evolves them, rather than generating a single solution

STOP vs Other Self-Improvement

  • STOP: Provides mathematical safety proofs for recursive improvement
  • Others: Improve without formal safety guarantees
  • Key difference: STOP proves that safety properties hold across improvement iterations

CER vs Simple Experience Storage

  • CER: Stores experiences with rich context and retrieves based on contextual similarity
  • Simple storage: Stores experiences by task type only
  • Key difference: CER enables transfer learning across related but different tasks

Trade-off Analysis

For Our Use Case (OpenCode Multi-Agent Pipeline):
  • Start with: Orchestrator-Worker pattern + Priority Queue Loop (from repos)
  • Add self-improvement: Implement SICA's self-editing approach
  • Add experience: Implement CER's contextual replay
  • Ensure safety: Apply STOP's safety principles for critical operations
  • Optimize over time: Use AlphaEvolve's evolutionary approach for prompt optimization
